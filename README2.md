# Feature layers

Add one layer at a time. Promote a layer only when validation log loss improves by at least 0.001 on the chronological 70/15/15 split. Leave earlier knobs fixed while a new layer is being tested. Score the test set once, on the model you decide to keep.

TrueSkill is layer 1 because it carries the pre-match signal. Each later layer is something that can still help after TrueSkill is in the model.

## Layer 1 — Team TrueSkill

The model. Everything else is an add-on.

- `team1_trueskill_conservative`, `team2_trueskill_conservative`
- Optional in the same layer: `team1_trueskill_mu`, `team2_trueskill_mu`, `team1_trueskill_sigma`, `team2_trueskill_sigma` (sigma is uncertainty, which conservative rating only partly captures)
- Source: `vallu_scraper/data/features/team_trueskill/`. The locked file from the sweep is `features_team_trueskill_6.000_2.000_0.100.parquet`
- Games played stays a row filter (`team1_games > 10` and `team2_games > 10`), not a feature

Team Elo is the alternative to this layer, not a column beside it. Rank and H2H belong in that same comparison if they get built. The promoted model keeps one rating family.

## Layer 2 — Match context

Small, known before the match, and it changes what later features mean. A map-pool or form sweep run without these flags can lock a setting that only fits BO1s or only fits online matches.

- `is_lan` (from `event_type == "LAN"`)
- `is_bo1`, `is_bo3`, `is_bo5`
- Event tier, when a column exists
- Fatigue, when it is built: days since each team's previous match, matches played in the last 7 days

These columns are already on the match parquet. `xgboost_2.py` builds `is_lan` and the BO flags and does not pass them to the model. The next experiment is this layer on top of locked TrueSkill.

## Layer 3 — Map pool

How the two teams differ by map, after overall strength is already in the model.

Compare one locked map-specific rating source at a time:

- Map Elo: `features_map_elo_190_90_17.parquet` at the feature root, with
  `*_elo_diff`, `best_map_elo_diff`, `map_pool_depth_diff`,
  `weighted_map_elo_diff`, and per-map games counts
- Map TrueSkill: generated by
  `feature_generation/features_map_trueskill_multiple.py`; includes per-team
  per-map mu, sigma, conservative ratings, and their differences

Evaluate map TrueSkill against map Elo on validation before combining rating
families. Then try one map win-rate window (`features_map_winrate_l5`, `l10`,
or `l15`) and keep it only if the rating features leave something on the
table. Veto preferences and side win rate join this layer when they are built,
and only from information known before the match starts.

## Layer 4 — Residual team form

What TrueSkill has not already absorbed. One window, chosen on validation: `features_rolling_l5`, `l10`, or `l15`.

- Diffs of `rolling_rating`, `rolling_kast`, `rolling_swing`, `rolling_win_rate`
- ADR joins this list when it is built

`xgboost_2.py` already adds l15 kast, swing, and win rate, on top of map Elo, with context still missing. Re-test this layer after layers 2 and 3 rather than treating that script as the locked form model.

## Layer 5 — Extra momentum

Only after layer 4 has been kept or rejected.

- Current win-streak difference
- Opponent-adjusted win rate over the same window as layer 4
- A second rolling window

Expect this layer to fail the 0.001 bar often. TrueSkill plus one rolling window already contain most of it. A rejected layer is a finished experiment.

## Layer 6 — Players

Last. Aggregate to the roster that actually played, at match time.

- Player ADR, KAST, or rating, rolled up to the team (mean, or mean of the top and bottom player)
- Role, clutch, and entry impact as team diffs

Skip per-player columns crossed with maps. That matrix is wider than 30k matches can support once stand-ins and missing rows are included.
